## WordPress REST API Autotests

Проект представляет собой автоматизированные API-тесты для проверки CRUD-операций над сущностью "Posts" в WordPress.

Тесты включают как позитивные, так и негативные сценарии, с обязательной проверкой фактического изменения данных в 
базе данных MySQL через JDBC. Во втором сьюте тестовые данные создаются и удаляются напрямую в БД с помощью SQL-запросов.

### Технологический стек
- **Java:** 25
- **Сборщик:** Maven
- **Тестовый фреймворк:** TestNG
- **API-клиент:** REST Assured
- **Работа с БД:** JDBC (MySQL Connector)
- **Генерация данных:** JavaFaker
- **Конфигурация:** Owner
- **Дополнительно:** Lombok, Jackson

### Архитектура проекта 


Проект построен по принципу разделения ответственности:

- `config` - классы для чтения конфигураций и настройки спецификации REST Assured.
- `db` - утилитный класс для взаимодействия с БД (JDBC), выполнения SQL-запросов и управления соединением.
- `dto` - Data Transfer Objects для сериализации запросов и десериализации ответов API.
- `endpoints` - хранение констант URL-эндпоинтов и настроек спецификации API.
- `steps` - классы, инкапсулирующие логику отправки API-запросов.
- `tests` - классы с автотестами.
- `utils` - вспомогательные классы (генераторы тестовых данных, кастомные ассерты).

### Предварительные требования

Для запуска проекта локально у вас должны быть установлены:

1. JDK 25
2. Apache Maven
3. Docker (для поднятия локального стенда WordPress и MySQL)

### Установка и запуск

**Шаг 1: Запуск локального стенда**
1. Запустить Docker-контейнеры с WordPress и MySQL.
2. Дождитесь инициализации WordPress, задайте логин/пароль администратора при первичном входе.
3. Активируйте плагин JSON Basic Authentication в админ-панели WordPress.

**Шаг 2: Настройка конфигурации**
1. В проекте перейдите в `src/test/resources/configurations/`.
2. Скопируйте файл `config.properties.example` и переименуйте его в `config.properties`.
3. Заполните `config.properties` вашими актуальными данными. (*Примечание: файл `config.properties` добавлен в
`.gitignore` и не попадает в Git из соображений безопасности*).

**Шаг 3: Запуск автотестов**
**Через IDE:** Откройте проект в IntelliJ IDEA, дождитесь индексации Maven и запустите класс PostCrudTests.java.

**Через консоль:** Выполните в корне проекта команду:
```bash
mvn clean test
```

### Описание тест-кейсов

Cьют 1: `PostscrudTests` CRUD-операции через API
1. `TC-001` Создание поста с валидными данными.
2. `TC-002` Редактирование поста (изменение статуса и заголовка).
3. `TC-003` Жесткое удаление поста (force=true).
4. `TC-004` Создание поста со значениями по умолчанию.
5. `TC-005` Безопасное удаление (перемещение в корзину без force).
6. `TC-006` Негативный: создание поста с невалидным статусом.
7. `TC-007` Негативный: редактирование несуществующего поста.
8. `TC-008` Негативный: удаление несуществующего поста.
9. `TC-009` Негативный: обновление поста с невалидным статусом.

Сьют 2: `PostsGetTests` получение данных через API, создание данных через JDBC
1. `TC-010` Получение данных поста по существующему ID.
2. `TC-011` Поиск постов по заголовку.
3. `TC-012` Поиск постов по контенту.
4. `TC-013` Фильтрация постов по валидному статусу.
5. `TC-014` Негативный: получение несуществующего поста.
6. `TC-015` Негативный: фильтрация постов по невалидному статусу.
7. `TC-016` Негативный: получение поста с невалидным форматом ID.
